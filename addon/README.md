# Anki 小工坊 · 模板一键安装（Anki 插件）

插件编号 **905039649**。两个功能：

1. 把本仓库的 11 套模板一次性装进你的 Anki 集合
2. 在网站生成完卡片后，**直接发送到 Anki**，不用下载再导入

```
工具 → Anki 小工坊 → 安装卡片模板…              勾选要装的模板
工具 → Anki 小工坊 → 启动 / 停止接收服务          站上「发送到 Anki」的开关
工具 → Anki 小工坊 → 显示配对码…                站上第一次发送时要填的 6 位数字
工具 → Anki 小工坊 → 接收服务状态…              已导入 / 失败 / 拒绝的次数
工具 → Anki 小工坊 → 打开模板展厅               到浏览器里看每套模板的真实效果
```

## 功能一：模板一键安装

一次装完 11 套模板，省掉「新建笔记类型 → 逐个加字段 → 粘贴正反面模板 → 粘贴 CSS」。

**只新增，不覆盖**：已存在同名笔记类型时直接跳过，绝不改动你已有的笔记类型。
改错别人的笔记类型是这类「一键安装」插件最容易造成的破坏。装完就是普通笔记类型，
卸载插件后模板照常存在。

## 功能二：从本站直接发送到 Anki（v1.1.0 新增）

在网站生成完卡片后点「发送到 Anki」，卡片**直接进你的集合**——不再走
「导出 .apkg → 在系统里找文件 → 在 Anki 里导入」这三步。

怎么工作：插件在本机 `127.0.0.1` 上开一个小服务，网页把打包好的 `.apkg` 投递过来，
由主线程导入。

**为什么传的是 `.apkg` 而不是卡片结构**：站点已经能生成完全正确的包（模板、CSS、
填空类型、互动题型的运行时全都对）。让插件去理解卡片结构，就得把那份逻辑在插件里
重写一遍，两边迟早不一致，而后果是用户导入的卡片长得不一样。所以插件只做两件事：
**收包、导入**，单一数据源留在站点。

### 关于网络与安全，说准确一点

- **模板安装功能完全不联网**，不需要账号，不上报任何数据。
- **接收服务会在本机开一个端口**（从 8765 起，被占就往上让，最多 11 个）。
  它**只绑 127.0.0.1**，外网机器连不上；插件自己**不会向外发任何请求**，
  也不上报任何数据——数据流只有「你的浏览器 → 本机端口」这一个方向。
- 三道校验缺一不可：**Host 必须是本机**（挡 DNS rebinding——恶意域名解析到 127.0.0.1
  来冒充本站）、**Origin 必须是本站**、**配对码必须匹配**。
- 不想开这个端口：菜单里「启动 / 停止接收服务」随时可关，或把 `config.json` 里的
  `auto_start` 改成 `false`。

## 安装

### 从 AnkiWeb 安装

Anki →「工具 → 插件 → 获取插件」→ 输入 **905039649**。

### 从文件安装（开发用）

1. 取 `dist/anki-studio-templates-<版本>.zip`（用 `python3 addon/build_addon.py` 生成）
2. Anki →「工具 → 插件 → 从文件安装…」→ 选这个 zip
3. 重启 Anki

## 开发

```bash
# 1. 重新生成模板数据（模板改了之后必须跑）
#    在模板源项目里执行：
python3 scripts/build_addon_templates.py

# 2. 三套测试，都在**临时收藏夹**里跑，不碰你的真实收藏夹
python3 addon/test_installer.py     # 模板安装：19 项断言
python3 addon/test_bridge.py        # 发送桥：19 项断言（含三道安全校验）
python3 addon/test_addon_glue.py    # Qt 胶水层：19 项断言（用假 aqt 加载整个插件）

# 3. 打包成 AnkiWeb 可上传的 zip
python3 addon/build_addon.py
```

### 目录

| 文件 | 作用 |
|---|---|
| `anki_studio_templates/__init__.py` | 菜单、弹窗、定时泵（Qt 部分） |
| `anki_studio_templates/installer.py` | 写笔记类型的纯逻辑，不依赖 Qt，可单独测 |
| `anki_studio_templates/bridge.py` | 发送桥的本机服务，不依赖 Qt，可单独测 |
| `anki_studio_templates/templates.json` | 模板数据（**生成物**，不要手改） |
| `anki_studio_templates/config.json` | 默认配置（配对码、端口、是否自动启动） |
| `anki_studio_templates/manifest.json` | 插件清单，`package` = 905039649 |
| `test_*.py` | 三套测试 |
| `build_addon.py` | 打包成根目录布局的 zip |

### 为什么逻辑要拆成不含 Qt 的文件

写集合的代码是有破坏性的，必须能被单独测；混在含 Qt 导入的模块里就只能靠手点。
拆开之后测试能直接用 Anki 自带的 `anki` 包开一个**临时集合**跑完整流程，
不需要启动 GUI，也不会碰到用户的真实数据。

### 已验证

按 **Anki 26.9.2** 的 API 编写并核对（反解 `app_packages` 里的 `.pyc`，确认
`ModelManager` 的 `new` / `add_field` / `add_template` / `add` / `by_name`、
以及 `Collection.import_anki_package` 等接口都存在），并在该版本的临时收藏夹里
跑通三套测试。

### 🔴 线程模型（改这个插件前必读）

Anki 的 Collection **不是线程安全的**，而接收服务跑在后台线程。
所以导入必须回到主线程执行：`bridge.pump()` 由 `__init__.py` 里的 QTimer 周期调用。
**千万不要图省事在 HTTP handler 里直接 `import_anki_package`**——那是在后台线程动集合，
症状是随机崩溃或数据损坏，而且不报错，最难查。

### 🔴 端口不是写死的

插件从 8765 起往上找第一个能用的端口，站点也从 8765 起逐个探到 8775。
两边必须是**同一个范围**。实测本机 8765 常被别的本地服务占用，写死单端口会让
「发送到 Anki」静默失效，而插件其实好好地跑在 8767 上。
